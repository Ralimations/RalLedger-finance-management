## Phase II implementation status

- Milestone A audit/freeze: complete for the current primary navigation, Home, Accounts, Activity, Planning, Insights, Settings, and Quick Add entry points. Specialized CRUD details continue to be tracked in `FEATURE_CRUD_MATRIX.md`.
- Milestone B interaction foundation: in progress. The app-bar Add action opens the shared Quick Action Hub from each of the five main destinations. Income, Expense, and Transfer open the existing transaction form in the selected mode. More routes to existing receivable, expected income, budget, bill/loan, subscription, savings-goal, and interest screens; add-capable items open their existing forms, while target-dependent actions open the relevant list. Quick Add prioritizes the saved account, then the latest eligible non-reversed transaction account, and uses the latest matching category when available. Its transaction form is a scrollable bottom sheet with an optional collapsed description, retained account balance context, a discard prompt after edits, and a synchronous save guard. The design palette now defaults to accessible Ocean blue and adds Coral and Amber choices. Planning's former 11-tab strip is now a grouped landing screen with focused module views and Android Back returning to Planning. Calculator-enabled monetary inputs now share `MoneyAmountField`. Settings now uses purpose-based sections with in-app and Android Back. Dashboard now has configurable journal-derived Recent Transactions, responsive money-owed cards, and corrected neutral Net Worth labels; dashboard and backup preferences migrate legacy six-card lists. Shared selectors/date controls, discard guards for specialized forms, analytics hierarchy, and screen-by-screen contextual CRUD consolidation remain open.
- Milestones C–G: not yet complete. Implemented controls and verification must be recorded as each slice lands; no existing module is considered complete from a visual mockup alone.

## Feature preservation rules

- Posted financial events continue through repository use cases and keep atomic correction/reversal history.
- Receivables never become spendable cash; savings allocations remain reserves, not additional assets.
- A selected quick action must open the corresponding existing operation and must not post until the user saves.
- Collect-payment and reconciliation actions require a target record/account, so the hub takes the user to the relevant list/detail context rather than guessing a target.
- Mockup data, references to cloud sessions/PINs, and fields the application does not persist are not implemented as real product data.
